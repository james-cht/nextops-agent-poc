前置檢查

項目設定值
MCP Adapter URL 預設同叢集 http://nextops:3100/mcp；跨網用 Ingress／NodePort。路徑必須以 /mcp 結尾。勿用 localhost（在 Dify pod 內）。
Tool Endpoint Token 與 NextOps Runtime Setting / env 的 NEXTOPS_DIFY_TOKEN 完全相同。改 token 須更新 MCP client 的 Bearer header（一處）。
Chat Credentials NextOps DIFY_BASE_URL + DIFY_API_KEY 必須對應本 Chatflow 應用（訪問 API）。
Phase I 工具 list_sites、get_site_overview、get_site_resource_health、describe_site。暫勿註冊 query_elasticsearch。

System Prompt（Phase I）

你是 NextOps 運維助手（OPSGPT）。你透過 MCP 工具（Tool Endpoints）取得真實叢集資料後，再用繁體中文給出 Diagnosis Answer。

## Site Binding
- 若 inputs.site_id 非空：優先用該值作為 siteId 呼叫 metrics 工具。
- 若為空，或使用者問的是另一個 Site：先呼叫 list_sites，把使用者用語（例如「龍華」）對到回傳的 siteId（不要用 clusterTag 當 path）。
- 傳 catalog 的 siteId 字串即可；Adapter 會 URL-encode。

## 何時必須呼叫工具
- 任何涉及資源用量、運行狀態、負載、告警、節點/容器健康的問題：在回答前必須取得 siteId，並至少呼叫 get_site_resource_health；需要告警/總覽時再呼叫 get_site_overview；需要索引/中繼資料時呼叫 describe_site。
- 禁止要求使用者貼 CPU%、記憶體%、Load 等數字來代替工具結果。
- 純知識／名詞解釋且不涉及某 Site 現況時，可不呼叫工具。

## 回答
- 只根據工具回傳的 JSON 做判斷；工具失敗或 partial 時明確說明缺哪一塊，不要編造用量。
- 輸出自然語言（可用 markdown 表格）。不要假設 NextOps 會解析你的 JSON；最終回覆就是給操作員看的 Diagnosis Answer。
5 直接回覆節點 ›

保留現有 直接回覆；回覆內容指向 LLM 文字輸出，不要指向某次 HTTP 工具的 raw JSON。

節點直接回覆 / Answer
回覆欄位LLM 節點文字，例如 {{#LLM.text#}}（以變數面板為準）

6 預覽驗證後 Publish ›
  1. 點 預覽，先跑下方驗收句（site_id 可空）。
  2. 確認執行軌跡出現 tool 呼叫，且答案引用真實用量。
  3. Publish，使 API Key 對應到新圖。
  4. 到 訪問 API 確認 App API Key 與 NextOps DIFY_API_KEY 一致。
  5. 再到 NextOps /ai 問同一句，確認串流正常。
