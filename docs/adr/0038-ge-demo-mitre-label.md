# GE demo labels one prepared event with a Mitre technique

The cybersecurity scene shows threat modeling as the STRIDE comment already produced by the GitLab CI job. The Mitre ATT&CK moment is a prepared event in `ge-sample` that NextOps labels T1609, Container Administration Command. Vertex explains that label. The demo does not run an exploit, does not move laterally, and does not take credentials.

Application Online remains Spec, the central Git merge request, Dev validation, and promotion. It is not the attack simulator. A live Mitre simulation would be a surprising extra product inside a module whose glossary job is promotion, and it would put an exploit next to the cluster hosting the talk.

## Considered Options

| Option | Outcome |
| --- | --- |
| Label one prepared T1609 event and explain it (chosen) | The video can say the control exists without attacking the cluster |
| Script T1609 and T1210 against live pods | Matches an earlier slide, and risks the demo cluster and any data it can reach |
| Claim Application Online already implements Mitre | The module does not. The claim would describe a product that is not there |

## Consequences

- Do not add a second Mitre engine beside the label on this event.
- Do not treat 應用上線 as the place an exploit runs.
