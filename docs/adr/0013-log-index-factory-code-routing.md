# ADR-0013: Log index routing by Factory Code

**Status:** Accepted (Smart Logging **UI / SSE filter chrome** — Mode toggle, Namespace/Pod combobox, facets discovery UI, level as primary chrome — superseded by [ADR-0021](0021-smart-logging-watchlist-document-filters.md). Factory Code routing, pattern validation, and “namespace/pod never rewrite the Log Index Pattern” remain.)

ADR-0004 keeps **backend SSE + ES polling** for Smart Logging, but a single env `LOG_INDEX` (default `filebeat-*`) plus document `cluster_tag` filters no longer match how logs are indexed. Upstream indices are **Factory Code–prefixed**. Documented segment shapes may include namespace/pod or year-week suffixes; observed production indices often use daily names such as `logs-{factoryCode}-k8s-es-log-{yyyy.MM.dd}`. We route by resolving a Site Log Index Pattern from Factory Code (or a validated operator pattern), not by a global catch-all index.

**Decision:** Each Site must declare `factoryCode` and `defaultLogMode` (`k8s` | `non_k8s`). Default query index is `{LOG_INDEX_PREFIX}-{factoryCode}-*` (prefix default `logs`). Smart Logging is **single-Site**; index targets are resolved under the Factory Code prefix (operator pattern or, after ADR-0021, the active Log Index Pattern from an Index Watchlist). Server validates operator patterns (must start with `{prefix}-{factoryCode}`, safe charset, length cap). Optional ISO-week (`yyyy.ww`) expansion is **off by default** (`expandWeeks: true` to enable) because week-expanded patterns miss daily production indices; time scoping uses `@timestamp` on the site wildcard. Expansion never rewrites a user-supplied pattern.

**Log Namespace / Log Pod** remain document fields (`kubernetes.namespace_name` / `kubernetes.pod_name`) and must **not** rewrite the Log Index Pattern. ~~UI: K8s mode only; combobox + facets…~~ **Superseded by ADR-0021:** Smart Logging uses Document Filters from raw JSON instead of Namespace/Pod comboboxes and facets; SSE drops dedicated namespace/pod/level params. `query_elasticsearch` may still accept `namespace` / `pod` for a compatibility period. Missing Factory Code is a hard failure for log paths. The same index-resolution module serves SSE, historical backfill, and `query_elasticsearch`; `describe_site.esIndices` stays metadata (default pattern `logs-{factoryCode}-*`), not facets. Wuhan (`wh`) remains out of scope until added fully.

**Considered options:** keep `filebeat-*` + `cluster_tag` (wrong contract); always query `logs-*` (too broad); put namespace/pod into the index string (zero shards against daily `k8s-es-log` indices); static per-Site namespace catalogs (stale); multi-select namespaces in v1 (deferred); facets on `describe_site` (no time window); dual-maintain old `k8s-events-*` / `syslog-*` describe lists (misleads the Dify Agent).

**Consequences:** ADR-0004’s transport choice stands; its **ES Index** section is superseded by this ADR. Replace `LOG_INDEX` with `LOG_INDEX_PREFIX`. Index assembly must stop injecting namespace/pod segments for query routing. Smart Logging chrome and SSE filter shape after Watchlist redesign → [ADR-0021](0021-smart-logging-watchlist-document-filters.md). Preference persistence → [ADR-0022](0022-smart-logging-preferences-local-settings-store.md).
