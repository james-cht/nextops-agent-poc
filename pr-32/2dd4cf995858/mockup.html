PR #32

介面審查修正版面 (Observe-Only Mockup)

● 發現一：資訊層級與狀態視覺化不足 agent-poc-status.html

問題：核心指標 ok: true 與 service 均為等寬字型純文字，鍵與值視覺權重完全相同，缺乏直覺視覺號誌。

影響：閱讀順序不明確，管理員無法在第一時間（半秒內）判斷該 Agent 是否正常運作。

改善：改為精準雙欄佈局，對齊 Label 與 Value，並為狀態值套用高對比語意化 Badge 與呼吸燈號。

● 發現二：空間密度低且缺乏容器擴充性 agent-poc-status.html

問題：原版 .card 使用固定寬度 max-width: 420px 且內距過大，置於頁面中央造成空間極度浪費。

影響：當未來系統規模擴展、需要同時監控多個 Agent 時，原有排版會瞬間破裂且不具併排彈性。

改善：解鎖固定寬度，改採響應式網格與彈性佈局，提高資料密度，支援多重服務同時監控。

● 發現三：缺乏異常與讀取中等狀態設計 agent-poc-status.html

問題：僅提供 ok: true 單一正常狀態，未考慮異常（error/offline）或載入中（loading）的狀態處理。

影響：當異常發生時，系統管理員極難迅速定位紅色警戒，且無法呈現系統暫態與載入狀態。

改善：建立多態（Healthy、Error、Loading/Warning）視覺模型，並在右側實作即時連動的詳情面板。
